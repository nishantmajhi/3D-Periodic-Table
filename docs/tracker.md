# 3D Periodic Table — Project Tracker

**Status**, newest first:

- **2026-10-01 — cleanup pass** (branch `cleanup/2026-10-01`; details in `review.md`). Clicks and hovers landed on the wrong tile: three.js counts a ray as hitting a line within 1 world unit, the tile outlines are 1.05 apart, so aimed at Fe a click opened Rh — true of all 88 floor tiles at the default view. The hidden pillar cubes could also be clicked through the gaps between tiles. Naturally occurring radioactive isotopes (U-238, K-40, Th-232 and 31 others) were shown as stable, and 13 of the "longest-lived" fallback isotopes were wrong (Lr-262 for Lr-266, and others). The isotope data is now generated by `tools/gen-isotope-data.mjs` from a vote of independent sources. Popped cuboids and atom views now free their GPU textures and buffers. Tests: 73 in `npm test`, 20 in headless Chrome. Touch was checked in emulation: a tap works, a drag is cancelled by the browser after a couple of moves (see Open below).
- **2026-08-19 — isotope mass-number glyph fix.** Digits (most visibly "1") in the popped isotope cubes' "mass N" label sometimes rendered as a corrupted stray mark instead of a clean numeral. Root cause was two compounding issues: (1) `isoLabelTexture` requested IBM Plex Mono at weight 600, but only weight 500 was ever loaded via the `@import` in `globals.css`, so that line could silently render in a fallback font; (2) all label canvases were drawn at a low, non-supersampled resolution (e.g. 220×220 for isotope labels) that's then magnified onto isotope cubes that can fill much of the viewport, so fine glyph details -- like IBM Plex Mono's numeral "1", which has a small top flag rather than a plain bar -- got destroyed by aliasing. Fixed by adding weight 600 to the IBM Plex Mono import, 3x-supersampling every label canvas in `textures.js`, and forcing plain linear filtering with mipmaps disabled on the resulting `CanvasTexture`s (mipmapping a magnified, non-power-of-two text sprite was adding blur risk with no benefit). As a defensive second layer, `CanvasStackLazy.jsx` now waits on `document.fonts.ready` (with a timeout fallback) before mounting the scene at all, since canvas text bakes in whatever font is available the instant it's drawn and never gets redrawn once the real font arrives later.
- **2026-08-19 — gap/floor-grid fix.** The marker-cell-to-pillar gap was ~0.56 units (far more than the ~0.19 edge-to-edge gap between ordinary adjacent tiles), and the floor `THREE.GridHelper` ran straight through that oversized gap, visually exaggerating the separation into looking like two unrelated structures. Pillar start offset now derives from the same `SP - TILE` spacing used everywhere else in the grid, and the floor `GridHelper` has been removed entirely.
- **2026-08-19 — scope pullback.** The decorative per-element/per-pillar-cube "isotope stub" cube clusters (hanging below every grid tile and sideways off every pillar cube) were removed — they were adding visual clutter without being interactive themselves. Isotope counts are still fully explorable by clicking an element (unchanged). Lanthanide/actinide pillars now hang *below* the main body instead of rising above it. Popped isotope cubes are now colored to match their parent element's category instead of a single fixed gold color for every element.
- **Before 2026-08-19.** UX/interaction prototype finalized (`periodic-table-prototype.html`, vanilla Three.js + GSAP, single file). Next.js/R3F scaffold built and building cleanly; perf and hover-easing issues found and fixed; isotope dataset is real NIST data; URL routing, lazy loading, and a further material-sharing perf pass are all done; a deep-link staging bug, a raycasting-accuracy bug, and redundant isotope-cube text were found and fixed; keyboard navigation + a screen-reader-friendly fallback are implemented; and the visual polish pass (real lighting, solid lit materials) is done.

**Open:** mobile/touch input.

**Core concept:** the periodic table is a "floor." Lanthanides/actinides are pillars hanging below their marker cell instead of detached footnote rows, with the same tile-to-tile spacing as the main grid so they read as part of one continuous structure. Isotopes for a clicked element live below the floor conceptually, but visually pop toward the viewer as a cuboid, colored the same as the element's category. Default view reads as an ordinary flat 2D table; tilting reveals it's 3D.

## ✅ Resolved architectural decisions (pre-port)

- [x] **Blur technique for R3F** — evaluated two-canvas `backdrop-filter` vs. `@react-three/postprocessing` depth-of-field via a standalone spike (plain Three.js + ES modules, mock tile grid + cuboid). **Decision: two-canvas approach**, matching the prototype almost exactly. Ports to R3F as two stacked `<Canvas>` elements sharing camera state through a store (Zustand or Context) so both cameras stay in lockstep every frame; `OrbitControls`/hit-layer writes to the store, both canvases read from it. The CSS `backdrop-filter` overlay div between them ports over unchanged.
- [x] **Isotope data scope** — evaluated stable-only vs. all-known-isotopes vs. stable+curated. **Decision: stable isotopes as the base list, plus a curated `notable` flag** for isotopes with outsized real-world relevance regardless of stability (U-235/238, C-14, Tc-99m, Co-60, I-131, etc. — same spirit as the existing hand-curated Hydrogen isotopes, generalized into a data field). Keeps typical per-element counts small (1–6ish) so the row → grid-wrap cuboid layout (below) stays viable without pagination/scrolling.
  - New isotope schema fields implied: `stable: boolean`, `notable: { flag: boolean, reason: string }`
- [x] **Variable isotope count UI** — single row up to ~5 isotopes, wraps to a 2-row grid beyond that. Reuses the existing reveal/separate/face animation logic per-cube; no new interaction model (e.g. drag-to-scroll) needed, so it doesn't conflict with orbit controls. Elements with zero stable isotopes (Tc, Pm, Z≥84) fall back to their notable-flagged isotopes instead of an empty cuboid.

- [x] Single `HitLayer` DOM overlay doing manual raycasting against tile/isotope-cube registries — ports the prototype's drag-vs-click detection and click handling directly
- [x] Full state machine (`overview → moving → popped → detail`) — kept imperative (GSAP driving raw Three.js objects via `popController.js`/`PoppedCuboid.jsx`), with `appStore` as a clean read-model for React UI (HUD, back button, detail panel)
- [x] Isotope cube + Bohr atom builders, camera-tilt pillar reveal, pillars, category key — all ported
- [x] Grid-wrap cuboid layout (`cuboidLayout.js`) implementing the resolved variable-isotope-count decision
- [x] `npm install` + `npm run build` both succeed cleanly (no missing imports, static page generation succeeds)
- [x] **Perf fix (stutter/dropped frames on all transitions, worst at isotope→atom dissolve):** root cause was `buildAtom()` constructing every nucleus/electron particle as its own `Mesh` with its **own freshly-allocated `SphereGeometry`** — for a heavy element (e.g. Uranium, Z=92) that's ~140 unique GPU buffer allocations landing synchronously in one frame, right as the isotope cube dissolves. Fixed by sharing geometry/materials module-level and rendering the whole nucleus + all electron shells via `THREE.InstancedMesh` (2-3 draw calls total, zero new geometry per atom). Also hoisted the redundant per-tile and per-pillar-cube `BoxGeometry`/`EdgesGeometry` allocations (118 + 30 previously unique, now 2 shared) to reduce steady frame overhead. Rebuilt and verified clean.
- [ ] **Still not visually re-verified locally** — the fix targets a clearly identified allocation spike, but hasn't been eyeballed in a live `npm run dev` session in this environment (same sandbox limitation as before). If stutter persists after this fix, the next suspect is the CSS `backdrop-filter` blur cost itself (expensive to keep recompositing every frame over two live WebGL canvases) — worth testing with the blur temporarily disabled to isolate it.
- [x] **Hover feedback fix** — hover scale-up/down was a hard `scale.set()` snap with no tween at all (not "harsh easing," just no easing), so it read as an instant jump rather than a hover state. Now eased via GSAP (`power2.out` in / `power2.inOut` out, 0.28s), with `gsap.killTweensOf` guarding against overlapping tweens when switching hover targets quickly, and explicit resets on click/drag-start/state-change so nothing gets left stuck mid-scale.
- [x] **Deep-link popped boxes landing off-screen fixed** — `/element/[symbol]` uses `useDeepLink.js`'s plain `requestAnimationFrame` poll to fire `popController.pop()` as soon as the target tile registers, which can win the race against R3F's very first `useFrame` (i.e. before `CameraRig` has ever applied the `cameraStore` transform to the actual camera). `pop()` was reading `camera.position`/`camera.getWorldDirection()` at that moment to stage the isotope cuboid in front of the camera — with a not-yet-synced camera, that "front of camera" was a direction the camera never actually ends up facing, leaving the popped boxes stranded off-screen and forcing the user to scroll/orbit to find them. Fixed by having `pop()` (`PoppedCuboid.jsx`) call `applyCameraState(camera)` itself first, so it's always reading the true current transform regardless of frame timing. Click-triggered pops were unaffected (by the time a user can click, the camera's already been synced for many frames) — this only ever showed up on direct/deep-link loads.
- [x] **Hover/click targeting accuracy fixed** — root cause: `HitLayer`'s raycasting camera is a standalone `THREE.PerspectiveCamera` that's never passed to the renderer. `camera.lookAt()` only updates `camera.quaternion`; it does not rebuild `camera.matrix`/`matrixWorld`. For the real render camera that's invisible because `WebGLRenderer.render()` force-refreshes a parentless camera's matrixWorld every frame — but nothing was doing that for the off-screen raycasting camera, so every hit-test was reading the _previous_ `applyCameraState()` call's rotation, one step stale. Fixed centrally in `cameraStore.js` by calling `camera.updateMatrixWorld(true)` right after `lookAt()`, so every consumer of `applyCameraState` (raycasting camera included) is immediately accurate rather than one call behind — most noticeable right after orbiting the view and then clicking.
- [x] **Redundant isotope-cube text removed** — each isotope cube's face showed three lines: the symbol (e.g. "Ca"), "mass 40", and the full `iso.name` ("Calcium-40") underneath — the third line just restated the same mass number the first two already conveyed. Dropped that line from `isoLabelTexture` (`textures.js`) and recentered the remaining two; `iso.name` is untouched everywhere else (still used in `DetailPanel`, where the symbol isn't already sitting right next to it).
- [x] **Accessibility implemented** — added `AccessibleOverlay.jsx`, a parallel keyboard/screen-reader UI that sits alongside the 3D scene rather than trying to make WebGL itself accessible:
  - **Keyboard navigation:** a roving-tabindex `role="grid"` mirroring the real `PERIODS` layout (arrow keys move between elements, Up/Down snap to the nearest matching group when rows have different gaps, Home/End jump to row start/end, Enter/Space opens isotopes). Lanthanides/actinides get their own `role="list"` below the grid instead of only being reachable via the marker cell + camera-tilt gesture — a real accessibility _win_, not just parity, since keyboard/screen-reader users get direct access to all 118 elements without ever needing to orbit the camera. A matching roving-tabindex list covers isotope selection once an element is popped, with focus handed off automatically between the element grid → isotope list → atom detail panel (and back) as the app state machine transitions, so keyboard focus always lands somewhere sensible instead of getting lost.
  - **Screen-reader fallback:** every interactive element is a real labeled `<button>` (off-screen via a standard `.sr-only` clip pattern — not `display:none`, so it stays in the accessibility tree and tab order); a visually-hidden `aria-live="polite"` announcer narrates element/isotope info and state changes on every focus/transition, since the 3D scene has no text equivalent otherwise; `Toast` now also has `role="status" aria-live="polite"` so the marker-cell "tilt to see them" message reaches screen readers too; `DetailPanel` gets `role="region"` and now takes programmatic focus when the atom view opens; both WebGL `<canvas>` elements and the pointer-only `#hit-layer` div are `aria-hidden="true"` since `AccessibleOverlay` now carries the real semantic content.
  - **Visual focus indicator for sighted keyboard users:** a `focusController` registry lets keyboard focus trigger the exact same GSAP hover-scale highlight mouse hover uses on the real 3D tile/cube — no separate on-screen indicator to draw or keep in sync, keyboard focus and mouse hover are visually identical by design.
  - Not covered (noted as a scope boundary, not a bug): lanthanide/actinide pillar cubes stay visually hidden until the camera is tilted past the reveal threshold, so the hover-highlight/focus-ring visual feedback for those specific elements isn't visible on screen until then even though selection works correctly regardless — full announcer/keyboard support is unaffected.

- [x] **Real isotope dataset sourced and integrated** — replaced the synthetic mass-number generator with real data from NIST's "Atomic Weights and Isotopic Compositions for All Elements" (fetched 2026-07-30, all 118 elements). Every element's stable/primordial isotopes now have accurate mass numbers and natural abundances (e.g. Sn correctly shows all 10 real stable isotopes; U shows the real primordial 234/235/238 with real abundances; Bi/Th/Pa/U are correctly _not_ in the "zero stable isotopes" set since NIST still reports their primordial abundances, unlike the earlier `Z>=84` placeholder heuristic which got this wrong). The curated `notable` list (Tc-99, C-14, Co-60, I-131, U-235/238, Pu-239) sits on top as before — that's still a small illustrative set worth expanding, but the base data is no longer a placeholder. See `src/data/stableIsotopeData.js` (since 2026-10-01, the generated `src/data/isotopeData.js`) for the data and provenance notes, `src/data/isotopes.js` for the merge logic. Verified against representative elements (Sn, Tc, U, F, C) via a standalone runtime test.

Clicking an element to see its full isotope cuboid is unaffected and remains the one place isotope counts are shown.
- [x] **Lanthanide/actinide pillars moved below the main body** (2026-08-19) — pillars now hang downward from their marker cell (negative Y) instead of rising upward above the table. Reveal-on-tilt behavior, occlusion handling, and click-to-pop-isotopes all carry over unchanged; only the direction flipped.
- [x] **Popped isotope cubes now colored per-element** (2026-08-19) — `buildIsotopeCube` took a hardcoded gold (`0xffb454`) fill color for every element's isotope cuboid; it now takes the clicked element's own category color (the same color as its tile/pillar cube), so e.g. clicking a noble gas pops purple-tinted isotope cubes and clicking an alkali metal pops red-tinted ones, rather than every element looking identical once popped.
- [x] **URL/state routing implemented** — `/element/[symbol]` and `/element/[symbol]/isotope/[mass]` dynamic routes deep-link directly to a popped element or its detail view (`useDeepLink.js` retries across a few frames until the target tile is registered, then drives `popController` exactly as a click would). As the user then interacts, the URL stays in sync (`urlSync.js`) via raw `window.history.replaceState` calls placed at each state transition in `popController` -- deliberately _not_ routed through `next/navigation`'s router, since `/`, `/element/[symbol]`, and the isotope route are distinct `page.jsx` files and a real Next.js navigation between them would unmount/remount the whole `CanvasStack` (and both live WebGL contexts) on every click. This keeps the address bar shareable without ever touching the live scene.
- [x] **Lazy loading implemented** — `CanvasStackLazy.jsx` wraps `CanvasStack` in `next/dynamic(..., { ssr: false })` with a lightweight loading screen, so the heavy three.js/@react-three/fiber/gsap bundle is code-split out of the initial page load entirely. Concrete before/after from the build output: the `/` route's First Load JS dropped from **~249 kB page-specific / 337 kB total** to **1.38 kB page-specific / 88.8 kB total** -- the 3D bundle now loads as a separate chunk only once the client mounts, rather than blocking the initial page payload.
- [x] **Additional perf pass: shared materials + centralized reveal updater** — pillar cubes and isotope stubs previously each created their own `MeshBasicMaterial`/`LineBasicMaterial` pair and wrote to it individually every frame (~150 separate per-frame opacity writes across ~148 component instances, on top of the geometry sharing already done). Since there are only 10 category colors used across the entire table, `materialCache.js` now caches one fill/edge material pair per `(type, color)` -- capping at ~20 materials total regardless of tile count -- and a single `<RevealSync/>` component updates all of them in one `useFrame` loop instead of each instance running its own. Per-instance `useFrame`s now only toggle `.visible` (unavoidable, since that's genuinely per-object) plus, for pillars, the one sprite-material opacity write that can't be shared (unique label texture per element).
- [ ] **Mobile/touch input** — current orbit controls are pointer-events based (should mostly work for touch) but untested; tap-vs-drag click detection threshold may need tuning on mobile. Note: the new `AccessibleOverlay` keyboard grid is a good fallback path to sanity-check on mobile screen readers (VoiceOver/TalkBack) even before touch-drag orbiting itself is tuned.
- [x] **Visual polish pass** — moved off the intentional "wireframe/blueprint" validation look to a solid, lit look: added `SceneLights.jsx` (hemisphere fill + ambient + a warm key directional light + a cool cyan-tinted rim/fill directional light, no shadow-casting lights/shadow maps to keep the earlier perf work intact) to both canvases, and switched every previously-unlit, mostly-translucent `MeshBasicMaterial` fill (table tiles, pillar cubes, isotope stubs, popped isotope cubes, atom nucleus/electron particles) to `MeshStandardMaterial` at near-opaque opacity so they actually shade under the new lights instead of rendering as flat tinted glass. Edge outlines switched from bright category-colored wireframe lines to a fixed dark neutral outline (`EDGE_COLOR` in `materialCache.js`) at low opacity — enough to keep adjacent same-colored geometry readable without the scene reading as wireframe again. Marker cells (La*/Ac*) get a small emissive boost to stay visually distinct now that low opacity can't do that job anymore. `CategoryKey`'s floor plaque intentionally stays an unlit textured plane (it's a flat printed legend, not a 3D object).
